# AGENTS.md

Бот для Discord. Python-версия в корне репозитория (`main.py`, `cogs/`,
`database/`) остаётся эталоном текстов и данных. Rust-версия живёт в `rust/`
и разворачивается независимо.

Стек Rust: `serenity 0.12.5`, `poise 0.7.1`, `songbird 0.6.1`, `sqlx 0.8`,
`sysinfo 0.33`. Решения и источники чисел: `rust/DECISIONS.md`.

Это правила, а не пожелания. Если правило делает задачу больше, сказать об
этом и сделать работу, не отменяя правило ради скорости. Отчитываться о том,
что произошло на самом деле: проваленный шаг цитируется, пропущенный шаг
называется с причиной. Проверенным не называется то, что не прогонялось.

## Сборка и проверка

```bash
cd rust
cargo build --release
bash scripts/gates.sh
```

`yt-dlp` должен быть в `PATH`. Для живой базы нужен `DATABASE_URL`, иначе
тест базы печатает «НЕ ВЫПОЛНЕНО» и это не успех.

## Ворота 1. Автотесты на реальном объекте

Моков нет ни в каком виде. Тест, который проходит и без проверяемой
возможности, не тест.

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test -- --nocapture
```

Проверяется на настоящих объектах:

- `tests/decode.rs` декодирует все mp3 из `music/` (6 файлов, 40 МБ) через
  symphonia. Если фичи кодеков в `Cargo.toml` отвалятся, тест упадёт.
- Разбор вывода yt-dlp проверяется на записи живого вызова в
  `tests/fixtures/`: это запись живого вызова yt-dlp от 2026-11-05.
  Синтетических фикстур нет; если файл удалить, тест честно печатает
  «НЕ ВЫПОЛНЕНО» и пропускается, а не считается пройденным.
- Upsert пользователя проверяется на живой PostgreSQL по `DATABASE_URL`.
- Имена и описания 11 команд сверяются с Python-версией в
  `commands::tests::surface_matches_python`.
- Правила имён файлов и путей проверяются на временных каталогах.

Когда компонент недоступен (нет базы, нет сети, нет токена), тест честно
печатает «НЕ ВЫПОЛНЕНО: причина». Отчёт, где это числится пройденным,
разбирается как ложная отчётность.

## Ворота 2. Проверка через интерфейс, как её делает человек

Владелец в своём Discord проходит команды: `/play`, `/stop`, `/batek`,
`/timur`, `/victorovich`, `/bomjara`, `/roflvideo`, `/kupyansk`,
`/grandmobile`, `/help`, `/batekfetch`. Агент интерфейс не подменяет.
Следы: журнал бота и ответы владельца.

## Ворота 5. Измерения

Метод до и после, иначе пары не сравнимы:

```bash
cd rust
date +%s && cargo build --release && date +%s
stat -c %s target/release/batekbot
```

- старт до ready: от запуска процесса до строки «ready за» в журнале;
- первый ненулевой VmRSS и пик VmHWM: опрос `/proc/<pid>/status` каждые 20 мс;
- горячий ответ на слеш-команду без сети: меньше 50 мс;
- `/batekfetch`: меньше 100 мс, скан пакетного менеджера удалён.

Регрессия против записанной базы это дефект, если не названа и не принята.

## Ворота 6. Запуск на настоящей машине

```bash
cp .env.example .env    # токен и пароль базы
docker compose -f docker-compose.rust.yml up -d --build
```

База поднимается пустой, миграции накатываются ботом. Проверяется, что после
рестарта контейнера кэш видео читается с диска и ready наступает без сети.

## Ворота 7. Документация

`rust/README.md` и `rust/DECISIONS.md`: каждое число со ссылкой на файл,
команду или измерение. Комментарий рядом с кодом объясняет, почему решение
такое и какое ограничение оно обслуживает. Проза на русском, без эмодзи, без
длинных тире, без маркетингового тона. Тексты ответов бота это отдельный
контракт: они остаются дословно как в Python-версии, включая мемы и
орфографию.

## Жёсткие контракты

- 11 слеш-команд, имена и описания дословно как в Python-версии.
- `users(id BIGINT PRIMARY KEY, username VARCHAR(100) NOT NULL)`. Уникальности
  по `username` нет и добавлять её нельзя. Личность это `id`.
- Активы не переименовывать: `video/bomjaro2.mp4` именно так, все шесть mp3 в
  `music/` как есть.
- Токен: переменная `main`, запасная `test`. Токен не логируется и не
  коммитится.
- Интенты: только `GUILDS` и `GUILD_VOICE_STATES`.
- `/play` принимает только имя файла из `music/`; абсолютные пути и `..`
  отклоняются.
- Вложения: `defer` до отправки, лимит 8 МиБ проверяется заранее.

## Telegram

Бот также слушает Telegram в том же процессе и контейнере
(`rust/src/telegram.rs`). Токен берётся из `TELEGRAM_TOKEN`; пустое значение
выключает Telegram одной строкой в журнале, Discord продолжает работать.
Bot API не умеет входить в голосовые чаты, поэтому `/play` и `/stop` там
только отвечают отказом. `/meme` берёт файлы из существующих `video/` и
`music/`: отдельного каталога нет, имя мема это stem файла. Inline-режим
отдаёт только cached-результаты с file_id, которые появляются после первой
отправки мема или прогрева через `TG_CACHE_CHAT` (числовой id чата, не
username). Telegram id пишутся в отдельную таблицу `tg_users`.

В группах и супергруппах бот отвечает на ключевые слова в обычных сообщениях.
Чтобы Telegram доставлял их, privacy mode должен быть выключен: BotFather,
`/setprivacy` -> Disable. Альтернатива сделать бота администратором группы.
Иначе бот видит только команды и упоминания.

Discord отвечает на те же слова, если в Developer Portal включён Message
Content Intent: Bot -> Privileged Gateway Intents -> Message Content Intent.
Отдельной переменной окружения нет. Перед созданием клиента бот читает флаги
приложения через `get_current_application_info()`: при
`GATEWAY_MESSAGE_CONTENT` или `GATEWAY_MESSAGE_CONTENT_LIMITED` intent
добавляется и реакции работают, иначе intent не запрашивается и бот пишет в
журнал, что ключевые слова выключены. Вслепую `MESSAGE_CONTENT` не
запрашивается: без галочки serenity завершается и бот умирает.

Список слов один на обе платформы: константа `KEYWORD_REACTIONS` в
`rust/src/keywords.rs`. Там же матчер: целые слова, транслитерация кириллицы,
без учёта регистра. Лимит 20 секунд на фразу в чате или канале. Вложения
Discord ограничены 8 МиБ, Telegram 50 МиБ.

## Git

- Тема коммита императивом, без точки, не длиннее 72 символов.
- Один коммит это одно изменение, рефакторинг отдельно от поведения.
- Автор из `git config user.name` и `user.email`; если не задано, спросить.
- Атрибуции ИИ, трейлеры и ссылки на сессии в коммиты не попадают.
- Пуш и релиз только после явного согласия владельца, каждый раз.
