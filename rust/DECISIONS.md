# Решения Rust-версии

Каждое число здесь имеет источник: команду, файл или измерение. Даты указаны
по машине, на которой шла работа.

## D01. Стек

`serenity 0.12.5`, `poise 0.7.1`, `songbird 0.6.1`, `sqlx 0.8`.
Версии взяты из crates.io API 2026-11-05; `poise 0.7.1` зависит от
`serenity ^0.12.5`, `songbird 0.6.1` от `serenity ^0.12.0` (crates.io,
зависимости версий), поэтому набор совместим.

## D02. Голос без ffmpeg

songbird не запрашивает кодеки у symphonia сам; без явных фич в нашем
`Cargo.toml` воспроизведение компилируется и молчит. Поэтому в зависимостях
`symphonia` с фичами `mp3`, `ogg`, `vorbis`, `wav`, `flac`, `pcm`, `aac`,
`isomp4`. Проверка на реальных файлах: `tests/decode.rs` декодирует все mp3
из `music/` (6 файлов, 40 МБ).

ffmpeg в образе не нужен: Python-версия запускала процесс ffmpeg на каждую
песню, Rust-версия декодирует в процессе.

## D03. DAVE

songbird 0.6.1 зависит от `davey 0.1.2` (crates.io, зависимости версии), то
есть протокол E2EE для голоса включён. Есть стороннее сообщение о разрыве
соединения с кодом 4006 через ~14 секунд из-за неотвеченного heartbeat
`seq_ack` в 0.6.0; для 0.6.1 это не подтверждено. Проверка: голосовое
соединение должно прожить больше 30 секунд. Статус: НЕ ВЫПОЛНЕНО, нужен
живой токен и гильдия.

## D04. Идентичность пользователя

Python искал строку по `username` и вставлял по `id`. При смене ника или
дубле имени это давало `MultipleResultsFound` либо нарушение первичного ключа.
Rust-версия делает один запрос
`INSERT ... ON CONFLICT (id) DO UPDATE SET username = EXCLUDED.username`.
Схема не меняется: `users(id BIGINT PRIMARY KEY, username VARCHAR(100) NOT NULL)`,
уникальности по `username` нет.

## D05. Кэш YouTube

Python вызывал yt-dlp шесть раз на импорте модуля, до подключения к гейтвею,
без таймаута. Rust-версия: последовательные вызовы в фоновой задаче, таймаут
120 с на вкладку с убийством процесса, слияние по вкладкам (упавшая вкладка
сохраняет прошлые данные), потолок 5 000 идентификаторов на вкладку,
атомарная запись `yt_cache.json` (временный файл и rename), чтение кэша при
старте до ready. Первый фоновый проход начинается через 3 с после запуска.

## D06. Пути

`BATEK_ROOT` (если задан), иначе текущий каталог с `music/` или `video/`,
иначе родитель текущего каталога, иначе текущий каталог. Чистая функция
`paths::resolve_root_with` покрыта тестами; файловые проверки идут в
`spawn_blocking` один раз при старте.

## D07. Защита `/play`

Аргумент принимается только если совпадает с именем файла из списка каталога
`music/`. `normalize_name` отклоняет пустую строку, `.`, `..`, `/`, `\` и
нулевой байт. Список кэшируется по mtime каталога. Тесты:
`library::tests::rejects_path_traversal_and_directories`,
`library::tests::lists_only_audio_and_resolves_known_file`.

## D08. Вложения

Файлы до 7.87 МБ (самый большой `video/kupyanskdis.mp4`, 7 868 318 байт,
`ls -l video/`) не успевали в трёхсекундное окно первого ответа Discord.
Rust-версия делает `defer`, проверяет размер против 8 МиБ и отправляет
следующим сообщением. Текст ошибки для слишком большого файла добавлен,
потому что в Python такого случая не обрабатывалось.

## D09. `/batekfetch`

Эфемерный ответ и только в гильдии. Скан пакетного менеджера удалён: его
результат нигде не выводился, а `dnf list installed` и `zypper` занимают
секунды. Данные снимает `sysinfo` в `spawn_blocking`. Гигабайты считаются как
ГиБ (деление на 1024³), как в Python-версии.

## D10. Измерения

Метод: `cargo build --release` в каталоге `rust/`, время от `date +%s` до
`date +%s`; размер через `stat -c %s`; старт до ready по строке журнала
(требует токен и гильдию).

Снято 2026-11-05, Arch Linux, rustc 1.99.1:

- холодная сборка: 733 с (12 минут 11 секунд по выводу cargo);
- релизный бинарник: 32 992 208 байт (после последней правки);
- инкрементальная пересборка после правки одного файла: 22 с.

- старт до ready, VmRSS, VmHWM, горячий ответ команды: НЕ ВЫПОЛНЕНО, нужны
  токен и гильдия на машине прогона.

## D11. Старт без внешних зависимостей

PostgreSQL больше не обязательна для запуска. `Db::connect` делает 5 попыток
по 1 с (`src/db.rs`), при сбое `Data.db` остаётся `None`, бот логирует
предупреждение и продолжает: музыка, `/help`, `/grandmobile` и `/batekfetch`
базу не используют, а `/batek`, `/timur` и `/victorovich` пропускают upsert
и пишут предупреждение один раз. Миграции выполняются только при успешном
подключении; их ошибка логируется и база отключается, процесс не выходит.

Регистрация слеш-команд вынесена из `setup` в фоновую задачу: `setup`
возвращает `Data` сразу, иначе сбой сети или 429 оставлял poise без user data
и каждое событие зависало, а живой процесс не давал `restart: always`
перезапустить контейнер. Регистрация делает 5 повторов с задержкой 5, 10, 20,
40, 80 с; провал логируется, команды остаются недоступны до перезапуска.
Ошибка `FrameworkError::Setup` теперь логируется и завершает процесс с кодом
1, чтобы супервизор перезапустил контейнер.

Фикстура `tests/fixtures/yt_playlist.txt` на этой машине не записана: каталог
пуст, поэтому `youtube::tests::parses_recorded_live_output` печатает
«НЕ ВЫПОЛНЕНО» и честно пропускается. Синтетическая запись не подставлялась.

## D12. Осознанные отличия поверхности

- У опции `filename` в `/play` есть описание «Имя файла из папки music». В
  Python описания не было, Discord показывал пустое место.
- `/stop` отвечает после `defer` (следующим сообщением), а не первым ответом:
  у songbird `get_info` без таймаута, и зависание дольше трёх секунд иначе
  давало «приложение не ответило».
- `DISK` в `/batekfetch` считается как `total - available` (sysinfo), Python
  считал `total - bfree`. На файловых системах с резервом для root значения
  отличаются на размер резерва.
- Обработчик ошибок отвечает эфемерно; в Python обработчика не было.
- Кнопки видео-команд принимает только автор команды; в Python нажимать мог
  кто угодно.
- Для отклонённых имён (`..`, `a/b`, обратный слэш) сообщение показывает
  исходную строку без дописанного `.mp3`, потому что нормализация невозможна.

## D13. Telegram в том же процессе

`teloxide 0.17` с `default-features = false` и фичами `rustls`, `macros`,
`ctrlc_handler` (`Cargo.toml`). `native-tls` не включается намеренно: рантайм
это Alpine/musl без OpenSSL (`rust/Dockerfile.alpine`). Проверка отсутствия
OpenSSL: `cargo tree -i openssl-sys` сообщает, что пакет не найден.

Токен читается из `TELEGRAM_TOKEN`. Пустое значение пишет одну строку
«Telegram выключен: нет TELEGRAM_TOKEN» и не мешает Discord. Диспетчер живёт
в отдельной задаче и перезапускается после ошибки с задержкой 5, 10, 20, 40,
60 с (`src/telegram.rs`, массив `BACKOFF`); `try_dispatch_with_listener`
возвращает ошибку первого `get_me`, поэтому паники нет.

Bot API не умеет входить в голосовые чаты, поэтому `/play` и `/stop` в
Telegram отвечают «голосовые команды работают только в Discord». Остальные
команды повторяют Discord; 90/10 и 50/50 сохранены.

Мемы не копируются в новый каталог: сканируются существующие `video/` и
`music/`, имя это stem файла (`src/memes.rs`). При совпадении имени видео
вытесняет аудио, иначе остаётся первый файл. Расширения: видео mp4/mov/webm,
фото jpg/jpeg/png/gif/webp, аудио mp3/ogg/wav.

Лимит загрузки 50 МБ из Bot API проверяется до чтения файла
(`TELEGRAM_UPLOAD_LIMIT`). Inline-режим может отдавать только cached-варианты,
потому что локальный файл в inline-ответ не подставляется. file_id
запоминается после каждой успешной отправки; `TG_CACHE_CHAT` (числовой id)
на старте отправляет первые 50 мемов и заполняет кэш, иначе inline пуст до
первого `/meme`.

Пользователи Telegram пишутся в отдельную таблицу `tg_users`
(`migrations/0002_tg_users.sql`), `users` не меняется. Запись идёт
fire-and-forget, ошибка только логируется.

## D14. Реакции на ключевые слова

Таблица слов, действие и матчер живут в `src/keywords.rs`, чтобы Discord и
Telegram не расходились в текстах и совпадениях. Матчер нормализует запрос и
фразу через `memes::normalized_words`: нижний регистр, транслитерация
кириллицы, только ASCII-буквы и цифры. Поэтому `бомжара` и `bomzhara` ведут к
одному действию, а `небомжара` не срабатывает: сравниваются целые слова.
Цифры на конце при этом не отбрасываются, иначе `бомжара2024` ложно совпала бы
с `бомжара`. Для «320» это важно отдельно: `1320` не совпадает.

`KeywordAction::RandomMeme` собирает все мемы по подстрокам и выбирает один
равновероятно. Так «бомжара» повторяет `/bomjara`: 50/50 между `bomjara1.mp4`
и `bomjaro2.mp4`, даже если `Memes::find` для `/meme` и inline выбирает
точный ключ первым.

Discord читает обычные сообщения только с привилегированным
`MESSAGE_CONTENT`. Запрос этого intent без включённой галочки в Developer
Portal (Bot -> Privileged Gateway Intents -> Message Content Intent) приводит
к завершению serenity. Поэтому intent не запрашивается вслепую: до создания
клиента бот вызывает `Http::new(token).get_current_application_info()` и
проверяет `ApplicationFlags::GATEWAY_MESSAGE_CONTENT` либо
`GATEWAY_MESSAGE_CONTENT_LIMITED` (`can_request_message_content` в
`src/main.rs`). Флаг есть: intent добавляется, обработчик включается, в журнал
идёт одна строка `info`. Флага нет или проверка не удалась: intent не
добавляется, обработчик выключен, в журнал идёт строка «ключевые слова в
Discord выключены, включите Message Content Intent в Developer Portal»;
процесс запускается как обычно. Отдельной переменной окружения нет.

Лимиты платформ отдельные: `KeywordLimiter` есть и в `Data` Discord, и в
`TgData`. Ключ это id канала или чата и совпавшая фраза; окно 20 секунд,
записи старше 10 минут удаляются при следующей проверке. Discord проверяет
`SEND_MESSAGES` и `ATTACH_FILES` по кэшу перед отправкой; если прав нет,
пишется предупреждение и повтора нет. Файл читается после проверки размера:
Discord 8 МиБ (`DISCORD_UPLOAD_LIMIT`), Telegram 50 МиБ
(`TELEGRAM_UPLOAD_LIMIT`).
