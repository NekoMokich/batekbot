# batekbot, Rust-версия

Независимая реализация бота на Rust. Python-версия остаётся в корне
репозитория как эталон текстов и данных; этот каталог собирается и
разворачивается отдельно.

## Стек

- `serenity 0.12.5` и `poise 0.7.1`: слэш-команды, кнопки, автокомплит.
- `songbird 0.6.1`: голос, DAVE через `davey`; локальные mp3, ogg, wav, flac
  декодирует `symphonia`, ffmpeg не нужен.
- `sqlx 0.8`: PostgreSQL, runtime-запросы, миграции вшиты в бинарник.
- `sysinfo 0.33`: данные для `/batekfetch` без вызова shell.
- `teloxide 0.17`: Telegram-бот в том же процессе, только rustls (в
  Alpine/musl нет OpenSSL, native-tls не включается).
- `yt-dlp`: внешний бинарник, только для перечисления идентификаторов видео.

Версии проверены по crates.io 2026-11-05, см. `DECISIONS.md`, D01.

## Сборка и запуск

```bash
cd rust
cargo build --release
BATEK_ROOT=.. ./target/release/batekbot
```

`yt-dlp` должен быть в `PATH`. Нужен токен бота. PostgreSQL не обязательна:
бот делает 5 попыток подключения по секунде, при сбое логирует
предупреждение и продолжает без базы; миграции применяются только при
успешном подключении. Без базы `/batek`, `/timur` и `/victorovich` работают,
но не записывают пользователя.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `main`, `test` | токен бота: берётся `main`, иначе `test` |
| `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME` | PostgreSQL |
| `BATEK_ROOT` | корень с `music/`, `video/`, `yt_cache.json` |
| `TELEGRAM_TOKEN` | токен Telegram-бота; пусто выключает Telegram, Discord работает |
| `TG_CACHE_CHAT` | необязательный числовой id чата для прогрева inline-кэша |
| `RUST_LOG` | фильтр журнала (`EnvFilter`), по умолчанию `info` |

## Docker

```bash
cp .env.example .env    # заполнить токен и пароль базы
docker compose -f docker-compose.rust.yml up -d --build
```

После правки `.env` нужен `docker compose -f docker-compose.rust.yml up -d`,
а не `restart`: `restart` переиспользует переменные, с которыми контейнер был
создан, и новые значения не подхватывает.

Основной образ собирается из `rust/Dockerfile.alpine`: `rust:1-alpine` для
сборки (musl), `alpine:3.22` для запуска. В рантайме только бинарник,
самодостаточный `yt-dlp_musllinux`, `ca-certificates`, `music/` и `video/`.
Процесс работает не от root (uid 10001).

Содержимое образа по `du -shx /` внутри контейнера: 130 МБ. `docker images`
показывает 250 МБ: в этом окружении BuildKit считает слои с запасом, поэтому
сравнивать надо `du`.

Зависимости собираются отдельным слоем с пустым `main.rs`, поэтому правка
кода пересобирает только наш крейт, а не двести зависимостей. Полная сборка
около шести минут, инкрементальная около минуты.

## Что изменено против Python-версии

Полный разбор дефектов и решений лежит в `DECISIONS.md` и в
`.slim/deepwork/rust-rewrite/progress.md`. Коротко:

1. Запуск больше не ждёт сеть: yt-dlp работает фоном, кэш читается с диска до
   ready. В Python шесть вызовов шли на импорте модуля, до подключения к
   гейтвею, без таймаута.
2. Один upsert по `id` вместо поиска по `username` и вставки. Гонка и
   падение на дубле имени убраны.
3. `/play` принимает только имя файла из каталога `music/`; переходы `..` и
   абсолютные пути отклоняются.
4. `/stop` освобождает голосовой канал; после конца трека бот выходит сам.
   В Python клиент жил до перезапуска процесса.
5. Вложения отправляются после `defer`, с проверкой размера 8 МиБ.
6. `/batekfetch` эфемерный; скан пакетного менеджера, результат которого
   нигде не выводился, удалён.
7. Только интенты `GUILDS` и `GUILD_VOICE_STATES`; `members` и
   `message_content` не запрашиваются.
8. Один обработчик ошибок команд: пользователь видит эфемерный текст, журнал
   получает команду и причину.
9. Команды регистрируются в фоне после `setup`, с пятью повторами и
   задержкой 5..80 с; сбой сети или 429 больше не блокирует user data.
   Если регистрация не удалась, команды недоступны до перезапуска, и это
   написано в журнале.

Поверхность команд и тексты ответов сохранены дословно; тест
`commands::tests::surface_matches_python` сверяет 11 имён и описаний.

## Discord: реакции на ключевые слова

Включаются одной галочкой: Developer Portal, Bot -> Privileged Gateway Intents
-> Message Content Intent -> включить и сохранить, затем перезапустить
процесс. Отдельной переменной окружения нет.

Перед созданием клиента бот спрашивает Discord
`get_current_application_info()` и смотрит флаги приложения
`GATEWAY_MESSAGE_CONTENT` / `GATEWAY_MESSAGE_CONTENT_LIMITED`. Если флаг есть,
добавляется intent `MESSAGE_CONTENT` и обработчик ключевых слов включается; в
журнале одна строка `info` «реакции на ключевые слова включены». Если флага
нет, intent не запрашивается и в журнале одна строка «ключевые слова в Discord
выключены, включите Message Content Intent в Developer Portal». Сбой проверки
даёт такую же строку уровнем `warn`; бот всё равно запускается.
`MESSAGE_CONTENT` никогда не запрашивается вслепую, потому что без галочки в
портале serenity завершается и процесс умирает.

В гильдейских текстовых каналах бот отвечает на те же слова, что Telegram:
«гранд мобайл», «белые розы», «бомжара» (случайный `bomjara1`/`bomjaro2`),
«макуос», «шефос» и их латинские и кириллические варианты. Таблица одна на обе
платформы: `src/keywords.rs`, константа `KEYWORD_REACTIONS`. Совпадение идёт по
целым словам с транслитерацией, поэтому `небомжара` не срабатывает.
Ограничение частоты: один ответ на фразу в канале за 20 секунд, записи старше
10 минут чистятся. Нужны права Send Messages, а для файлов ещё Attach Files;
при их отсутствии пишется предупреждение и повтора нет. Вложения Discord
ограничены 8 МиБ (`DISCORD_UPLOAD_LIMIT`), у Telegram лимит 50 МиБ
(`TELEGRAM_UPLOAD_LIMIT`).

## Telegram

Telegram-бот запускается в том же процессе и контейнере, если задан
`TELEGRAM_TOKEN`. Без токена в журнале появляется одна строка «Telegram
выключен: нет TELEGRAM_TOKEN», и Discord работает как обычно. Сбой Telegram
не роняет процесс: диспетчер перезапускается с задержкой 5, 10, 20, 40, 60 с.

Команды повторяют Discord, кроме `/play` и `/stop`: Bot API не умеет входить
в голосовые чаты, поэтому они отвечают «голосовые команды работают только в
Discord». Добавлен `/meme [имя]` и inline-режим.

Мемы берутся из уже существующих `video/` и `music/`, отдельного каталога
нет. Имя мема это stem файла: `video/bomjara1.mp4` доступен как `bomjara1`.
Дубликат имени разрешается в пользу видео, иначе остаётся первый файл.
Mp4/mov/webm уходят как видео, jpg/jpeg/png/gif/webp как фото, mp3/ogg/wav
как аудио. Файл больше 50 МБ не отправляется.

Inline-режим отдаёт только `cached`-результаты: Telegram требует file_id,
а он появляется после первой успешной отправки мема. `TG_CACHE_CHAT`
(числовой id чата) прогревает кэш на старте первыми 50 мемами. Пустой запрос
показывает статью «Выберите команду» со списком команд, случайные шортс,
видео и мем, затем до 20 мемов из кэша; запрос без совпадений отвечает
статьёй «Ничего не найдено».

В группах и супергруппах бот отвечает на ключевые слова в обычных сообщениях:
«гранд мобайл», «грандмобайл», «grandmobile» присылают тот же текст, что
`/grandmobile`; «белые розы» и «бомжара» (случайный `bomjara1`/`bomjaro2`)
присылают соответствующий мем. Совпадение идёт по целым словам без учёта
регистра и алфавита, не чаще одного ответа на фразу в чат за 20 секунд,
записи старше 10 минут чистятся. Список слов общий с Discord и задан одной
константой `KEYWORD_REACTIONS` в `src/keywords.rs`.

Чтобы Telegram доставлял обычные сообщения группы, у бота должен быть
выключен privacy mode: BotFather, `/setprivacy` -> Disable. Альтернатива
сделать бота администратором группы. Без этого бот видит только команды и
упоминания, и реакции на ключевые слова не приходят. Личные чаты для
ключевых слов игнорируются.

Telegram id пишутся в `tg_users` через `Db::ensure_tg_user`, ошибка базы
только логируется и не мешает ответу.

## Тесты

```bash
bash rust/scripts/gates.sh
```

Тесты идут по настоящим объектам, моков нет:

- `tests/decode.rs` декодирует все mp3 из `music/` через symphonia;
- разбор вывода yt-dlp проверяется на записи из `tests/fixtures/`; на этой
  живой записи 2026-11-05 (три идентификатора с канала SravneniyaOfficial),
  тест падает, если парсер перестанет понимать реальный вывод;
- upsert проверяется на живой PostgreSQL, если задан `DATABASE_URL`;
- правила путей и имён файлов проверяются на временных каталогах;
- `memes::tests` проверяют разрешение дублей, поиск без учёта регистра и
  классификацию расширений на временных `video/` и `music/`.

## Измерения

Машина: Arch Linux, rustc 1.99.1, каталог `rust/`.

| Что | Значение | Как снято |
|---|---|---|
| Холодная сборка `cargo build --release` | 733 с | `date +%s` до и после |
| Размер релизного бинарника | 32 992 208 байт | `stat -c %s target/release/batekbot` |
| Инкрементальная пересборка после правки кода | 22 с | `date +%s` до и после |

Не проведено на машине сборки: старт до ready, VmRSS и VmHWM, горячий ответ
слеш-команды, время `/batekfetch`. Для них нужен токен, гильдия и живая база;
цифры вписываются после прогона владельцем, незаполненное значение это
непроведённое измерение, а не ноль.

## Известные ограничения

- Голосовое соединение дольше 30 секунд и поведение DAVE требуют живого
  токена и гильдии, на машине сборки не проверялись.
- `/batekfetch` показывает системные данные процесса в контейнере, а не
  хоста.
